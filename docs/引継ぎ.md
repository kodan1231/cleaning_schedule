## 0. このプロジェクトは何か

民泊（Airbnb）1〜複数物件の清掃を、チーム4名で回すための
**清掃スケジュール + チェックリスト + 写真エビデンス管理アプリ**（PWA）。

- 技術: Cloudflare Workers + Hono 4.x + D1（SQLite）。写真は当面 D1 BLOB 保存。
- ドキュメント（`docs/`）:
  - `01_要件定義書.md`（v1.1・承認済）
  - `02_基本設計書.md`（v0.4）
  - `04_開発環境セットアップ手順.md`（v0.1）
  - `05_実装計画.md`（v0.1、P0/P1 完了）
  - `03_チェックリスト定義.md` は未作成（実項目は運用開始後に admin が UI 登録する方針）
- 実装計画のフェーズ: **P0 基盤 → P1 認証 → P2 物件/テンプレ管理 → P3 iCal同期 →
  P4 清掃一覧/詳細 → P5 チェックリスト → P6 写真** で MVP。P7 PWA / P8 仕上げ。

## 5. 注意点・ハマりどころ

- **`page()` は `c.html()` ベース**（`src/views/layout.js`）。`new Response()` で返すと
  `setCookie` の Set-Cookie が消える。P1 でこのバグを踏んで修正済み。新しい画面関数も
  `page(c, opts, status)` / `authedPage(c, opts, status)` を使う。
- cookie の `Secure` は https の時だけ付く（`src/auth.js` の `cookieBase(c)`）。ローカルhttp対応。
- Airbnb iCal の実フィールド値（SUMMARY / DTEND がチェックアウト日か等）は**未検証**。
  P3 で実 URL を1物件登録して要確認（`docs/02 §5.3`）。iCal URL はユーザーが最初のメッセージで
  提示済み（`docs` には未記載、機微情報として扱う）。
- `wrangler.jsonc` の `vars` に `ICAL_URL` は入れない（旧コードの名残。新コードは物件ごとにD1保存）。
  push で `wrangler deploy` が走ると Worker 上の `ICAL_URL` 変数は消えるが、新コードは使わないので可。

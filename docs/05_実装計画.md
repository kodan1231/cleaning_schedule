## 1. 方針

- フェーズ単位で「動く状態」を積み上げる。各フェーズ末にローカルで動作確認。
- 早い段階でデプロイし、実データ（Airbnb iCal）でパーサを検証する。
- UI は最小限のスタイルで機能優先。デザイン磨きは最後。

## 5. リスクと対応

| リスク | 対応 |
|---|---|
| Airbnb iCal の形式が想定と違う | P3 で早期にデプロイし実データ確認。パーサをデータ駆動に |
| D1 容量（写真）が早く逼迫 | `/admin` で監視、閾値超で R2 移行（02 §7.4） |
| PIN の総当たり | 試行制限＋Secure cookie＋URL非公開（02 §6.2） |
| Workers 10ms CPU 制限 | 画像処理はクライアント側。サーバーは I/O 中心 |
| `assets` と動的ルートの競合 | 静的は `public/` 固定パス、動的ルートは接頭辞を分離 |

## 5. シークレット / ローカル環境変数

### 5.1 本番（Cloudflare Secrets）

```powershell
# 32バイト以上のランダム。例: PowerShell で生成
node -e "console.log(require('crypto').randomBytes(32).toString('base64url'))"

npx wrangler secret put SESSION_SECRET
npx wrangler secret put SETUP_TOKEN
```

- `SESSION_SECRET`: cookie/CSRF の HMAC 鍵。
- `SETUP_TOKEN`: セルフ登録 URL 用トークン（4名に配布。例 16〜24 文字のランダム）。

### 5.2 ローカル（`.dev.vars`、git 管理外）

```
SESSION_SECRET=ローカル用のランダム値
SETUP_TOKEN=local-setup-token
APP_TZ=Asia/Tokyo
APP_NAME=民泊清掃(dev)
```

## 6. ローカル開発

```powershell
npm run dev
# → http://localhost:8787
```

- D1 は `--local`（`.wrangler/state` の SQLite）を自動使用。
- Cron のローカル実行テスト:

  ```powershell
  # 別ターミナルで（wrangler dev 起動中に）
  curl "http://localhost:8787/__scheduled?cron=0+*/3+*+*+*"
  ```

  （wrangler の `--test-scheduled` 相当。実装後に同期処理が走ることを確認）

- ローカル DB のリセット: `.wrangler/state/v3/d1` を削除して §4 を再実行。

## 7. デプロイ

```powershell
npm run deploy
# → https://cleaning-schedule.<subdomain>.workers.dev
```

初回デプロイ後の作業:

1. `SESSION_SECRET` / `SETUP_TOKEN` が設定済みか確認（`npx wrangler secret list`）。
2. 本番 D1 にスキーマ適用（§4 の `--remote`）。
3. `https://<url>/healthz` が 200 を返すこと。
4. `https://<url>/register?token=<SETUP_TOKEN>` で管理者本人が最初に登録（admin 付与）。
5. `/admin/properties` で物件を1件登録し、iCal URL を設定 → 「今すぐ同期」。
